# Macro Shelf-A 0.9.5.1

发布日期：2026-09-28。作者：Akl。DalamudCN API 15 / .NET 10 / Windows x64。

插件简介：**当我受够了FF14那糟糕的宏指令**。

## 本次更新

- 0.9.5.1 精简设置文案：开关仅显示“原生宏执行”，下方仅显示“整段交给游戏执行。”，删除原说明区其余文字。
- 保留 0.9.5.0 新增的 `RaptureShellModule.ExecuteMacro` 原生执行路径；整段保留命令原文和 `<wait>`，不再由旧逐行执行器拆解等待或插入切职闸门。
- 长宏按最多 15 条有效命令分段，等待末行等待及游戏延后队列结束再续接，不增加固定延迟或动作重试，不占用/覆盖用户游戏宏槽位。
- 保留旧逐行执行器、原有三主题、原图、宏正文及已有功能。升级不自动启用新执行器，配置格式仍为 9 / 交换格式 5。

## 必须主动启用原生执行

更新后输入 `/aklmacro version` 确认 **0.9.5.1**。在“行数与等待设置”启用“原生宏执行”，或输入：

```text
/aklmacro engine native
/aklmacro engine status
```

长宏需开启“允许超过 15 行”；需要小数等待时确认对应等待补丁已成功启用。升级会保留已有配置，**默认关闭原生模式**；仍使用旧模式时不会使用本次动作兼容路径。停止后可用 `/aklmacro engine legacy` 明确切回旧模式。

## 实测与已知诊断

在执行逻辑相同的 0.9.5.0 中，针对一份 69 行舞蹈宏，视频中占星技能之后原先缺失的蹦跳已恢复，后续动作继续到末行。游戏日志记录两轮 5 段完整执行，总时长约 106.95 / 106.81 秒；另观察到一次插件自身停止的取消记录。没有把这一个样本扩展为所有宏、所有客户端或音轨逐拍同步已通过。

**保留已知 `CancelMacro` 签名校验提示。** 在启用框架签名校验的环境，首次初始化取消 Hook 可能记录 `HookVerificationException`：插件 Byte 返回与捆绑 ClientStructs 的 Void 声明不同。精确客户端机器码及调用方使用 AL 返回，插件因此保留 byte 透传；已检查框架记录错误后仍创建 Hook，本次正常运行样本未因该诊断中断。本发布不改成 void 来消除日志、不关闭校验，也不声称日志完全无错误。游戏原生取消/外部宏接管尚未全面实测。

## 兼容范围与边界

- 原生路径仅支持当前精确审计客户端 SHA256：`7BA28760BC53CBBBF66B63105FEA6C1BFE09CB6B1C6353FC8FB0FF03CC1A30F4`。不匹配时拒绝启动，不自动回退；清单 `ApplicableVersion=any` 不代表原生模式支持所有版本。
- 超过 15 行是分段原生宏，不是无限长单宏逐帧等价；空白与 # 注释沿用插件规则忽略，宏编辑正文不变。
- 多段宏含已知 `/mlock`、`/macrolock`、`/macroerror`、`/merror` 时拒绝整次运行，防止分段重置局部状态。
- 已有原生宏先等待最多 30 秒，不抢占；游戏已接纳的延后动作遵循原生取消行为，不承诺停止后回滚已发生的动作。
