## 0.8.4.0：切职顺序修正

数字 `/gs change N`、`/gearset change N` 发送后，只有角色对象、玩家状态、热键栏三处职业和目标套装一致，才继续后续宏行。聊天、表情、中文动作、技能、独立 `/wait`、跨子宏及下一次切装都遵守相同顺序，同职业不同套装也核对编号。

被阻塞的行不会提前消耗，显式等待从该行实际执行时完整计算；切装行自身的等待仍从切装命令发送时开始。普通宏额外行间隔为 **0**，每帧最多一行，没有固定稳定延迟或动作重试。

首次实际阻塞起 **10 秒**仍未同步就中止整段宏并提示；中止、登出或角色身份变化会清理等待。主窗口与常用栏显示“等待职业与套装同步”，收起后仍可中止。有效目标的初始角色状态不可用时，不发送切装命令。

支持的目标格式为数字编号 1 至 100，可带数字幻化参数。套装名、相对编号、其他切装别名及无法读取职业的目标不在本版目标解析范围，继续交由游戏处理。

本次在线更新也包含此前本地 0.8.3 系列的原生命令入口修正：使用 `ProcessChatBoxEntry` 保留游戏外层准备、反馈与收尾；提供版本查询和默认关闭的可选动作诊断。

## 已知问题与验证边界

此前用户有效复现中，切装后约 18 毫秒，表情已在原生执行器返回 True，但职业与套装尚为旧状态。旧保护只覆盖 `/ac`、`/action`，表情越过保护提前派发。

**该提前派发缺口已在代码中修正，是否解决全部动作/技能失效仍待游戏内验收。** 职业与套装一致不等于原生技能缓存、冷却或动画已就绪，也不能仅凭命令入口返回判断动作成功。

Release 构建 0 警告、0 错误；**260/260 逻辑检查、98 项主窗口和 196 项常用栏断言通过**。窄窗口、150% 缩放、收起后的中止与后续状态恢复已通过离线回归。逻辑使用模拟游戏状态，UI 使用原生 ImGui 离线宿主，不等同游戏内验收。

## 原有功能与兼容性

保留分类与搜索、A+B 主编辑界面、独立常用宏栏、宏组衔接、单独子宏运行、可选解除 15 行限制、每宏最多 64,000 字符、小数等待、倒计时触发和整段中止。配置版本 **8**、导出格式 **4**，已有宏与收藏无需重建。图标沿用用户原图，未重绘。

- `/aklmacro`：主界面
- `/aklmacro bar`：常用宏栏
- `/aklmacro stop`：中止运行
- `/aklmacro version`：实际加载版本
- `/aklmacro trace on`、`trace status`、`trace off`：可选短宏诊断，默认关闭，需要客户端精确校验；有次数和时长上限
