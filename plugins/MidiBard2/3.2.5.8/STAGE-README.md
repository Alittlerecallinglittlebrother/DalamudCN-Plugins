# midibard2-深海回响特供版

版本 `3.2.5.8`（v0.8 在线仓库版），Dalamud API 15，Windows x64 / .NET 10。作者：akira0245, Ori, Kalle, Zune, 断水剑。基于 `reckhou/MidiBard2` 的 `v3-api15-stable`，提交 `d8d1bd4454604cc837affd593fc3b982f33433e7`。这是深海回响定制分支，不是官方发行版，不含 OBS 联动。

新增“队员查看”：同一演出房间容纳一名队长、一名主持人和最多七名只读队员。队长与主持人共同管理队列，队员同步查看当前曲目、下一首及待演顺序。打开“自动点歌 → 演出房间”，队长创建房间，分别复制主持人邀请和队员查看邀请。沿用现有樱花 TCP 隧道，无须增加隧道或服务。配置和步骤见 [STAGE-ROOM.md](STAGE-ROOM.md)。

## 在线安装

在卫月设置的“自定义插件仓库”中添加 `https://raw.githubusercontent.com/Alittlerecallinglittlebrother/DalamudCN-Plugins/main/repo.json`，保存后刷新插件安装器，搜索 `midibard2-深海回响特供版` 并安装或更新至 `3.2.5.8`。已添加过该仓库时直接刷新检查更新。

安装前停用原版或旧版开发插件。本分支沿用 `MidiBard2` 内部标识和配置路径，不可与原版或其他 MidiBard2 开发版本同时启用。升级前备份插件配置。

本次对应源码为 `MidiBard2-Deepsea-3.2.5.8-source.zip`，在线仓库中命名为 `plugins/MidiBard2/3.2.5.8/MidiBard2-source.zip`，包含全部修改、构建脚本和许可。实际游戏内演奏及多人合奏尚待验收。

## 日常使用

1. 打开 MidiBard 底部的“自动点歌”。已有曲库直接沿用；曲库为空时自动导入 MidiBard 当前播放列表。同步图标可再次导入，文件导入仍在“曲库”页。
2. 选择“单人演奏”或“合奏主控”，进入乐器演奏模式，点击“开始连播”。该按钮同时开启点歌接收。
3. 观众在说话或悄悄话发送 `点歌 曲名`。完整曲名、别名或唯一部分匹配会直接排队；自然演奏结束后，间隔指定秒数自动载入下一首。队列清空后继续等待新点歌。

齿轮可调整频道、口令、每人待演上限、重复点歌间隔、队列上限和歌曲间隔。默认每人 2 首、同曲 30 秒冷却、队列 50 条。不同观众点同一首会各自排队，不自动合并。

同名多版本或未收录歌曲显示在“需要处理”。点击“选择歌曲”，再选一个版本即可入队，无须二次确认；稍后解决的旧点歌排在较晚收到且尚未演奏的点歌之前，不打断当前曲目。暂不演奏可直接取消。

加号用于自己加歌。队列支持上移、下移和取消。单人暂停会暂停当前曲；合奏暂停让本曲播完再暂停连播。合奏尚在准备时按下一首会取消准备并暂停连播，避免残留倒计时启动错误曲目。

## 合奏

- 在队长的主控端启动队列。同机多开使用 MidiBard 客户端同步，多设备使用原生 PMD 小队切歌命令。
- 多设备各端必须预先有相同顺序的播放列表和对应 MIDI、轨道及乐器配置。此版本不会替远端下载文件或校验远端 MIDI 哈希。
- 各端开启 MidiBard 合奏监听。建议各端使用本版本，载入或切乐器期间暂停自动确认准备；主控载入完成后发起原有准备确认。
- 只有收到真实 Playback Started 事件才记为开始。准备超过 90 秒未开奏会停止连播并保留待演曲目。
- 自然结束后结束本轮合奏并等待其退出，再准备下一首。实际多人同步、网络延迟及游戏内准备流程仍须游戏内验收。

普通队员想查看演出顺序时，先升级本版，再在“演出房间”选择“队员查看”，粘贴队长提供的查看邀请并加入。队员端不需要运行樱花启动器。列表随队长或主持人操作更新；查看角色没有加歌、排序、删歌或控制连播的权限，也不接收聊天点歌。查看模式不代替原合奏跟随和曲目配置，不会主动停止原 MidiBard 跟随播放。离开房间后恢复本机曲库视图。

## 历史与旧数据

旧曲库、节目单、点歌和记录保留。优先沿用原点歌接收的节目单；尚未设置时使用当前节目单。已有唯一匹配的待处理点歌会自动安排。自动队列略过串场和休息。

节目单、手动场控、开演检查和演出记录放在“更多”。自动演奏不要求先检查、开始场次或手动归档，播放记录自动保存。

重载插件后不会自动开奏。上次未结束的曲目可点击“重新排队”，保留原先的中断记录。保存失败时暂停推进，排除磁盘问题后点击“重试保存”；尚未落盘的事件只暂存内存。

数据仍位于 `%APPDATA%/XIVLauncherCN/pluginConfigs/MidiBard2/Stage`，以顶部文件夹按钮打开的路径为准。Schema 3 新增可选设置字段。回退前停用新版，并恢复升级前的数据备份。

## 开发插件安装

使用独立目录中的 `MidiBard2.dll` 作为卫月开发插件入口。`MidiBard.Stage.dll` 与 `BardStage.Core.dll` 是依赖，不是单独的插件入口。

自行执行 `build-dev.ps1` 后，可停用在线版或旧版开发插件，添加 `%APPDATA%/XIVLauncherCN/devPlugins/MidiBard2-Deepsea-v0.8/MidiBard2.dll` 并启用。在线版、原版和各个开发版本不可同时启用。升级时保留原目录和数据备份，不混拷 DLL。队长、主持人和查看队员建议统一更新至 `3.2.5.8`。

## 构建

安装 .NET SDK 10 和 Dalamud API 15 开发文件后运行 `./build-stage.ps1`。它执行核心测试、真实无输出设备 Playback 检查、原生 ImGui 检查，再编译集成插件。`./build-dev.ps1` 生成独立开发目录并逐文件校验，`./package-stage.ps1` 生成插件、对应源码及截图压缩包。

详情见 `STAGE-VERIFICATION.md`。`STAGE-IPC.md` 描述本分支的状态通知接口；自动队列在内部直接调用 MidiBard 播放器。
