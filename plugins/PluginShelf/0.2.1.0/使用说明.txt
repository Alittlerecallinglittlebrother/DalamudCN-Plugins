插件收纳盒 / PluginShelf 0.2.1.0
==============================

目标
独立的 Dalamud / 卫月 API 15 插件。常用插件入口收纳 + 分组启停总控。
点击收藏名称打开插件界面；每行右侧勾选框单独启停插件；整组按钮批量启停。
不会把其他插件的界面嵌入窗口，也不安装或删除插件。

0.2.1.0 同名副本修复与独立开关
- 收藏列表、收藏夹、分组成员、分组快捷面板均直接显示每个插件的独立“启用”勾选框。
  勾选 = 启用，取消 = 停用，仅影响这一项；不会开关整个组或改变组成员名单。
- 常驻条的收藏右键菜单也有“启用这个插件 / 停用这个插件”。
- 全部插件默认同时显示已启用与未启用插件，避免关掉后条目消失、找不到打开按钮。
- 同名副本旁有“副本 / 选择副本”按钮，可查看类型、版本、完整 DLL 路径和卫月编号。
- 不再只报错要求回卫月处理；在本插件中选择一次需要的副本，点“记住此副本”，以后单项与整组都使用同一份。
- 唯一正在运行的副本仍可自动识别；从收纳盒停用后会记住它，避免全部停用后无法再打开。
- 多个副本已经全部停用时，再点停用正常跳过，不误报歧义。
- 不按版本号或目录顺序擅自挑一份；记住的副本失效时提示重新选择，不切换到另一份。
- 指定一份后可以只停用它；如另一同名副本仍在运行，不会同时加载第二份。
- 配置升级至 v3，保留 v1/v2 收藏和分组；新增副本选择记录。升级前建议另存 shelf.json。

针对“存在多个同名安装/开发副本”
1. 找到 MidiBard2 那一行，点右侧“副本”（全部插件页为“选择副本”）。
2. 根据版本和完整 DLL 路径选中你正在使用的那一份，点“记住此副本”。
3. 再勾选该行“启用”，或点“整组启用”。保存副本选择本身不会启动插件。
4. “已经启用，未重复加载”是正常跳过，不是报错。
5. 可在选择窗口“恢复自动选择”；这只清除绑定，不启停插件。

0.2.0.0 状态识别修复与分组总控
- 读取目录改为逐插件、逐字段容错。缺失版本号或异常界面入口不会让整个目录刷新失败。
- 目录读取失败显示“状态未知”，不再把没有查到的收藏伪装成“插件未加载”；恢复后自动重新识别。
- “分组总控”页支持新建、重命名、编辑成员、删除分组；最多 32 组，每组 128 个插件。
- 每组“整组启用 / 整组停用”，收藏夹内也有“分组开关”，不必每次打开管理面板。
- “全部插件”页增加单插件启用/停用按钮。它与“打开主界面 / 设置”是不同动作。
- 串行执行：启用按勾选顺序，停用按逆序；重复成员去重，已在目标状态的插件跳过。
- 显示逐项结果及成功/原已满足/失败/未执行统计，不把“请求已发送”当作启停成功。
- 操作中禁止重复排队；可“停止后续操作”，等待当前插件完成后停止，不回滚已完成项目。
- 进入战斗停止后续队列；战斗中不允许开始启停。不能加入或操作收纳盒自身。
- 原收藏、名称、顺序与布局保留。配置升级为 v2，首次保存时 .bak 保留旧文件；之后 .bak 会滚动更新。

分组使用
1. 打开收纳盒 -> 分组总控 -> 新建分组。
2. 填写组名，勾选需要的插件；未启用插件也能加入。保存名单不会执行任何动作。
3. 点击“整组启用 / 整组停用”。这里的“停用”是停止插件运行，不是关闭窗口；不删除 DLL 或插件配置。
4. 常驻条点“收纳” -> “分组开关”，也可直接操作。管理页的“上次操作 · 逐项结果”查看失败原因。
5. 一个插件可在多个分组；分组没有互斥或引用计数，最后一次明确操作决定状态。
6. 需要服务先启用时先勾选服务再勾选依赖项；停用自动逆序。取消勾选再加入可将成员移到末尾。

重要兼容边界
- 当前 API 15 没有公开启停接口；分组通过窄范围反射调用本机卫月安装器同一路径。
- 仅更新目标插件所属的唯一卫月合集条目，再调用标准 LoadAsync/UnloadAsync；卫月保存启停意图。
- 不调用“应用所有合集”，不删除/重建合集，不修改其他成员，不绕过卫月的加载检查。
- 安全模式、API 过期、加载/卸载异常、同名副本歧义、归属多个合集、所属合集未启用或角色过滤不符时，显示失败原因。
- 内部接口变化时拒绝执行而不是强行调用。真实第三方插件可能有自身依赖或卸载问题。
- 启用失败会尽可能恢复该条目先前的启用意图；发生异常后请以卫月实际状态为准，不自动重试。
- “停止后续操作”不强杀正在运行的第三方构造/释放过程，因此可能需要等当前插件完成。
- 本包已做本地编译、核心/后端回归和真实 cimgui 离线界面验证，尚未连接游戏验收。

功能
- 自动读取已安装插件，排除自身，同内部名称优先采用已加载实例。
- 主界面与设置入口分别收藏，无须填写指令。
- 收藏列表与常驻快捷栏，名称/内部名称/中文别名搜索。
- 右键修改别名、默认动作或移除；右键也可临时打开其他公开界面。
- 收藏列表拖动排序；快捷栏解锁后可排序，拖动 :: 移动整条栏。
- 横/竖布局、双字缩写、缩放、常驻入口数、战斗隐藏、位置找回。
- 服务器信息栏的“收纳盒”鼠标入口（若全局隐藏该栏，请从插件自身设置找回）。
- 高级手动命令绑定。只调用当前注册的插件命令，不把文本发送到聊天频道。
- 多个不同命令可分别收藏；保存不会执行任何命令。
- 独立配置，原子替换并保留上一份 .bak；损坏/未来版本/外部改动时停止覆盖。
- 暂时未加载、卸载或失去入口的插件保留收藏，显示不可用原因。

显示说明
常驻条使用文字快捷按钮，展开面板使用紧凑列表；不依赖下载第三方图标。
公开入口的实际行为由目标插件决定，可能是显示/隐藏切换。
界面显示“已发送打开请求”仅指派发完成，不表示已检测到目标窗口。
快捷栏采用 Dalamud ImGui 绘制，不修改游戏原生快捷栏。

本地加载（一次设置，之后可全程鼠标使用）
1. 将插件压缩包完整解压到一个固定目录；不要只复制 PluginShelf.dll。
   PluginShelf.Core.dll、PluginShelf.json 和 PluginShelf.deps.json 保持与其同目录。
2. 在 Dalamud 设置的 Experimental / 实验性页面，找到 Dev Plugin Locations / 开发插件加载位置，
   添加解压后的 PluginShelf.dll 完整路径，启用该条目并保存。
3. 在插件安装器的 Dev Tools / 开发工具 -> Installed Dev Plugins / 已安装开发插件中，
   扫描并启用“插件收纳盒”。可设置启动时加载。不同汉化版本的标签可能略有差异。
4. 首次加载会显示收纳面板：点“全部插件”，为常用插件收藏“主界面”或“设置”。
5. 完成后关闭管理面板：常驻按钮直接点击使用，其余入口点击“收纳”后在收藏夹内选择。
   从旧版更新时，先退出游戏或卸载旧开发插件，将新包所有文件覆盖原解压目录，再加载；无需删除 shelf.json。

可选找回命令（正常使用不需要记）：
  /pluginshelf       打开收纳面板
  /pshelf            同上
  /pluginshelf dock  显示快捷栏并打开面板
  /pluginshelf reset 将快捷栏移回屏幕内并显示

配置及回退
配置为当前 Dalamud 插件配置目录下 PluginShelf/shelf.json；上一份为 shelf.json.bak。
仅本插件操作 shelf.json，不读写其他插件的配置文件。明确点击启停时，会通过卫月的合集接口保存目标插件启停意图。
若需回退旧版，请更新前另存 shelf.json；旧版会拒绝覆盖 v3 配置，避免丢失分组和副本选择。
若提示配置只读：停用本插件，备份 shelf.json 和 .bak，检查日志并修复配置后再加载。
要退回原来的使用方式，停用“插件收纳盒”即可；其他插件不受影响。
本次制作没有注册开发加载位置、没有热加载到现有游戏，也没有发布网络仓库。

源码构建
需要 Windows x64、.NET SDK 10、匹配的 Dalamud API 15 开发依赖。
优先使用参数 -DalamudHome，其次 DALAMUD_HOME 环境变量；否则自动寻找国服/国际服 Hooks/dev。
在源码根目录执行（PowerShell 7）：
  .\build.ps1
  .\build.ps1 -Validate -UiTests
或指定实际 SDK：
  .\build.ps1 -DalamudHome '完整的 Hooks\dev 路径' -Validate -UiTests
代码不捆绑 Dalamud 或游戏 DLL；它们由用户的 Dalamud 安装提供。
UI 测试使用本机 cimgui 和 Windows 微软雅黑字体；测试截图使用合成插件目录，不是游戏截图。

工程
PluginShelf.Core         配置、搜索、排序、动作校验、单次派发及原子保存
PluginShelf              Dalamud 接入与生产 ImGui 界面
PluginShelf.Core.Tests   不依赖 Dalamud 的核心回归
PluginShelf.BackendTests 真实 SDK 接口 + 隔离模拟后端集成回归
PluginShelf.UiTests      直接绘制生产界面的原生 ImGui 鼠标/布局回归

本版本没有实现
安装/更新/删除其他插件、插件界面嵌入、云同步、自动场景切换、手柄导航、专用 IPC 适配。
自定义命令不自动推断归属，请仅绑定自己确认过的目标插件打开命令。
测试通过不等于游戏内已加载或所有第三方插件行为均验证；请按随附验收清单进行真实环境确认。
